### 4. Looping over all layers / "Layer X ... total=... passed=... failed=..." summary

The per-layer summary lines are printed at the end of `run_action` (`gkeyll/lua/Tool/runregression.lua:2110-2128`):

This always iterates the full `LAYERS` array (moments, vlasov, gyrokinetic, pkpm — defined at line 48-53) and prints a summary line for **any layer that ended up with `cnt.total &gt; 0`**. `layerCounts` is populated as tests are added/run based on each test's `test.layer` field (set in `addCTest`/`addLuaTest`), which — per the bug traced above — can include `pkpm` (and potentially `moments`/`vlasov` too) even when the user only intended to run one gyrokinetic C test, because:
- `detectedLayer` was never set (since `-r`'s value isn't a bare layer-name token), so `list_tests()` scans `layersToScan = LAYERS` (all four), and
- The relative-path `--run-only` match in `addCTest` bypasses the absolute-path layer-affinity guard, letting the same file get inserted into `cTests` once per layer in the scan loop.

So you'd see up to four "Layer ..." lines (moments/vlasov/gyrokinetic/pkpm), each showing `total=1 passed=... failed=...` for what the user thought was a single, gyrokinetic-only test — and the compile scratch dir for the "pkpm" copy is `pkpm/creg-runs/rt_gk_ltx_iwl_2x2v_p1`, matching the reported "pkpm/creg/rt_gk_ltx_iwl_2x2v_p1" naming.
